# easyserp 产品与推广执行方案

## 对外定位

**easyserp：为开发者和 AI Agent 提供 Google、Bing 搜索，支持 2000 QPS。注册赠送 1000 次，之后 ¥2/1000 次。**

开源接入包提供 SDK、CLI、MCP 和 Skill。easybrSearch 是自家免费的浏览器研究工具；两个入口服务不同使用习惯，共同把搜索结果用于实际任务。

## 从成熟产品中取舍

| 借鉴对象 | 我们采用的做法 | 交付状态 |
|---|---|---|
| Serper / SerpApi | 清楚的引擎选择、结构化结果、地区/语言/分页、用量说明 | SDK、CLI、文档已准备；线上来源范围与中文表现待继续复测 |
| Tavily / Exa | 标准 MCP、明确的工具说明、少步骤接入、按任务选择来源 | 本地 stdio 已实现；托管 MCP/OAuth 后续落实 |
| Firecrawl | 把“发现链接”与“读取正文”区分，正文再进入回答 | Skill 已约定证据范围；正文读取可衔接 easybrSearch，未把全文抓取写成现有 API 能力 |
| TikHub / Apify | 统一入口、平台与工具发现、能力清单、可重复执行的结果回执 | 后续社媒服务端适配采用此结构，先逐项验证而非一次性堆平台数量 |
| 千瓜 / 新榜 / 蝉妈妈 | 按内容任务筛选，再输出有用途的对照与建议 | 先提供找资料、找案例、竞品对比示例；达人/成交/历史数据库不是当前接口交付物 |

## 搜索质量与效率

1. 把自然语言需求整理成少量互补查询，保留用户明确的平台、时间、地区和来源范围。
2. 同一批次独立查询并行；客户端默认 4 个工作槽，可配置为 1–32，避免 Agent 一次占满服务能力。大规模业务由服务端配额与任务调度管理。
3. 第一轮先看标题、链接和摘要，由当前宿主 AI 选择需要读的少量来源；全文读取再按预算执行。避免默认把所有网页全文塞入上下文。
4. 原始搜索结果保留，来源筛选、去重与相关性判断是单独的处理步骤。不得将引擎放宽 `site:` 的结果说成已满足用户范围。
5. pending、终态失败、网络未知结果分别返回；恢复沿用已知请求 ID 或相同幂等键，防止重发造成多次计量。
6. 固定中英文语料记录有效结果、来源命中、返回时间、实际费用与可回答性。质量检查和吞吐检查分别记录。

## 平台扩展

预留 Provider 合约：平台标识、搜索、详情读取、分页、能力声明、错误与人工交接。新增平台优先实现适配器和测试，通用 Skill 只维护选择与证据约定；仅在能力语义变化时扩展指令。

Google/Bing 的服务能力与浏览器原生自媒体搜索分开声明。先明确用户需求，再逐项评估抖音、小红书、B 站、微博、知乎、CSDN。每个平台显示实际支持的字段与当前验收状态；登录或验证受阻时返回人工处理入口，其他平台继续。

## 发行与推广

1. **接入转化**：入口页讲清能力与价格，注册后创建 Key，直接复制第一条成功查询；再提供 API、MCP、Skill 三种接入方式。
2. **第一批入口**：开源仓库与 npm、SkillHub、ClawHub；使用同一个版本、同一个能力清单，保存独立提交和审核回执。
3. **开发者生态**：MCP 官方目录、Smithery、Glama、skills.sh，并配套 Codex/Cursor/Claude/VS Code 接入文档。托管 MCP 完成后再展示真实地址。
4. **内容传播**：准备三类可复现案例——开发资料检索、品牌/竞品资料比较、自媒体选题研究。每篇给出查询、真实返回、耗时和接入指令，导向免费 1000 次体验。
5. **产品联动**：easybrSearch 免费研究 → 按用户任务推荐 easyserp 的批量 API；搜索资料需要继续用于写作、配图、多账号多平台发布时，再介绍 aimeGeo 的相应工作流。
6. **优化优先级**：看注册→建 Key→首次成功搜索→持续调用的转化率，以及查询缺口和用户问题。用这些数据决定增强顺序。
